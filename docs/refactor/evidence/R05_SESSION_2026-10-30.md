# R05 Claude native Messages evidence, 2026-10-30

ClaudeBackend now registers through the shared application factory and sends
native /messages with x-api-key, anthropic-version2023-06-01, separate system
instructions, block messages and native tool schemas. No Chat Completions parser
or wire payload is used for Claude. Model IDs are owner configuration.

ClaudeStream validates message/block lifecycle, event/type identities, open and
unique contiguous block indices, fragmented/interleaved JSON, tool IDs, matching
stop reasons and cumulative usage. Only a complete message_stop authorizes a
canonical turn. Input token totals include cache creation/read counters; output
is the final cumulative count. Truncation, malformed/missing lifecycle, unsafe
unknown content blocks and bad signatures fail explicitly. Future metadata event
types are ignored without gaining dispatch authority. Cancellation and early
cleanup use the shared bounded byte/SSE transport.

Thinking/signature/redacted blocks remain adapter-private and are replayed intact
with current request tool_use blocks. Tool results use user-role tool_result
blocks, preserving is_error and tool_use_id; adjacent user results/text merge in
order. Prior-request public records are quoted as historical data with original
role/provenance labels and leading guidance, avoiding invented private state.
There is no durable private protocol resume. A bound integrity-checked envelope
rejects request/key/profile/scope/instance changes before HTTP.

Options are closed: max_tokens, adaptive/disabled thinking and explicit effort.
AUTO omits thinking unless configured; enabled requests use adaptive thinking.
Unsupported manual thinking budget/temperature controls reject before HTTP; no
model-name inference or deprecated manual budget is silently sent. Direct native
capability gates also cover explicit options and tool-loop support. Owners must
configure a model/profile that actually supports chosen controls; HTTP rejection
is surfaced, never presented as feature success.
