# R02 implementation checkpoint

Initial checkpoint: R02 was in progress. Later verification and the core-contract
completion record are appended below. This is not whole-refactor/native/live acceptance.

Implemented in the existing single ChatRuntime:

- Bounded, adapter-owned `ProviderContinuation` carries private protocol data
  between model/tool rounds of one request. Payload is excluded from canonical
  serialization and repr, as is the enclosing field on settings/turns. Validation
  errors hide input. The runtime does not parse vendor state. Adapter binding and
  vendor protocol correctness remain R03–R06; durable provider resume is not
  implemented. A new request starts without the previous request's state.
- Model settings omit API keys from serialization/repr and hide validation input;
  the adapter still receives the existing resolved credential. This does not yet
  replace legacy credential persistence with a credential-reference store.
- A shared normalized stream validator rejects missing/duplicate terminal events,
  invalid event objects and events following completion. Runtime waits for stream
  validation before dispatching tools; the nonstreaming collector also consumes
  the entire validated stream. Invalid-stream regressions assert no tool dispatch.
- Command input/outcome contracts bind all normalized run fields in an approval
  hash; reject elevation/read-only assertions, invalid shells and bounds; preserve
  explicit partial-output and unknown-outcome semantics; require observed exit
  codes for success/failure and verified process-tree termination for timeout/
  cancellation. These are domain contracts, not a deployed command runner. R08/R09
  must wire authorization, target ownership, transports and transient retention.
- Architecture checks enforce domain/core independence from HTTP/API, prohibit
  domain imports of implementation and concrete provider imports in runtime,
  resolve relative imports, and match vendor module boundaries precisely.

## Expanded core boundaries

Shared application inputs now live in `contracts/application.py`; HTTP imports
these rather than owning the only input schema. MutationMode is a domain enum;
persistence/runtime/API import it there, with a compatibility re-export for
existing callers of mutation_authorization. Existing payload shapes are retained.
The generated OpenAPI diff adds only the enum description.

New immutable model-profile/capability contracts express protocol, explicit
capabilities, credential reference, JSON option snapshot and context/request/
transport/retry bounds. Per-adapter option validation, registry selection,
credential storage/migration and actual native vendor protocols remain R03–R06.
Skill descriptors pin package digest/version and scope; project guidance rejects
other projects and Device Chat, and development audience is excluded. Loader,
resource trust, lifecycle and script authorization remain R10.

The runtime now validates public event namespaces and JSON payloads before
persistence/logging, rejecting SDK objects or private envelopes. MCP configuration
has an explicit supported schema version. Existing transport negotiation and
lifecycle still belong to the MCP adapter; R11 conformance remains separate.

Expanded checks found and corrected these real defects:

- Stream-only structural test backends had no inherited validated_stream method;
  moved normalized validation to a common iterator wrapper. Diagnostic/cancel
  coverage was rerun: 80 focused tests pass, five new contract modules pass mypy.
- Rejecting malformed streams initially left upstream generators open. Five
  regression cases reproduced this; the validator now closes upstream in finally.
  59 protocol/deadline/diagnostic tests pass after the fix.
- OpenAPI generation never entered ASGI lifespan and left SQLite open during
  Windows temporary-directory cleanup. Explicit store close fixes this; generated
  schema differs only by the new domain MutationMode description.
- Strict mypy rejected Any returned by the JSON freezing helper. A typed cast of
  the validated recursive JSON snapshot fixes that static error.
