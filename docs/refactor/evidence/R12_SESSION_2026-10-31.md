# R12 implementation and validation in progress

Working-tree implementation, no commit/push. This report does not close native,
packaging, browser, live-provider, mobile or signing gates.

Implemented one local-owner identity across browser and native API access. Native
enrollment uses short-lived single-use codes; access/refresh tokens are opaque and
stored as SHA256 digests only. Atomic rotation detects recognized replay and
revokes the family; random invalid values cannot revoke a known family. Family
expiry/rotation/capacity are bounded. Restart preserves valid sessions; managed
restore revokes copied sessions/codes without modifying the original bundle.

The outer native bearer boundary validates only owner routes, rejects duplicate
Authorization headers and never falls back to browser cookies after invalid
bearer authentication. Worker/pairing credentials stay separate. Browser cookie/
Origin checks remain active; native public exchanges accept explicit bounded JSON
secrets, not ambient cookie authority. Desktop views bind a native family or
browser cookie, so two cookieless native clients cannot steal each other's views.

Request admission is durable and atomic by client UUID plus actual session/owner/
workspace/content hash. Identical retries return the same request; changed intent
conflicts. An application-owned task adopts the request once into ChatRuntime.
Restart does not replay an interrupted model/tool loop. SSE disconnect ends only
observation. Event pages use stable request-scoped UUID anchors, survive VACUUM,
bound rows/bytes and support query cursors or Last-Event-ID. Family revocation or
browser expiry ends ongoing observation. Ordinary Stop/shutdown owns execution.

Added scoped skill catalog/package/preferences/removal; bounded in-memory ZIP
uploads share the existing product parser/catalog/version pinning policy. No
server filesystem paths, extraction or scripts. Added configuration-only version/
doctor/target discovery and command list/status/cancel through actual scope and
CommandService; command creation retains the canonical authorized tool path.

OpenAPI now describes manually bounded endpoint bodies, required transfer/desktop
headers, native owner access and binary/NDJSON/SSE responses. A deterministic
stdlib generator produces owner operation/schema types and transport descriptors,
rejecting external refs, missing access classification and duplicate IDs. The
shared SDK has browser-cookie/native-vault modes, pinned canonical origins,
redirect refusal, bounded JSON, stream handling, single-flight refresh and exact
admission-only network retry. Native OS bridges remain R15–R17; UI adoption R13
and headless CLI integration R14 are not already complete.
