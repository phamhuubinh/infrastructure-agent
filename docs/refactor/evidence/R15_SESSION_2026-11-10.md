# R15 backend cho ứng dụng Windows

Đã triển khai entrypoint nội bộ `orion serve --managed` để native host chạy cùng
ASGI app trên cổng loopback do hệ điều hành chọn. Host gửi token phiên qua stdin.
HTTP và WebSocket kiểm đúng một header trước khi tới API. Header được lấy ra khỏi
ASGI scope sau xác thực. Backend chỉ báo origin sau readiness và dừng khi host
đóng pipe. Managed mode dùng cấu hình local riêng và giữ lifecycle của app hiện có.

Đã thêm recipe đóng gói `OrionBackend.exe` từ wheel cho Windows x64. Builder dùng
venv riêng với hash lock, đóng gói Python runtime và ghi manifest SHA-256 theo
file. Artifact này được cấu hình làm resource của ứng dụng Tauri.

Windows source subprocess test đã xác nhận readiness, HTTP từ chối token thiếu,
sai hoặc trùng, endpoint enrollment vẫn được bảo vệ và stdin EOF dừng sạch.
WebSocket test xác nhận từ chối trước dispatch và xóa header xác thực khi chuyển
request hợp lệ vào app.

Native Windows x64 đóng gói từ CPython 3.12.16 chuẩn, kiểm đủ 840 file theo
manifest. Chạy `OrionBackend.exe` với PATH/PYTHONPATH/PYTHONHOME trống đã qua
readiness, auth, chat stream qua HTTP provider fixture cục bộ và shutdown.
SHA-256 executable là
`08be36f0c713baa78646b17e99d7730caa13e2e2957617709e69699b1723ce39`.
SHA-256 wheel đầu vào là
`2b6bd05277f225de913f8a650983800a57d855556e6e507ff993139f8fe4411d`.
Windows CI có bước đóng gói và chạy lại managed-backend test trên executable.
Đây là bằng chứng cho backend đóng gói. R25 vẫn cần ứng dụng Tauri hoàn chỉnh.

## Shared client

Windows UI có thể nhận origin loopback do native host cấp lúc khởi động. Shared
SDK dùng transport riêng cho backend đi kèm và transport cùng vault theo origin
cho server remote. Màn hình kết nối hỗ trợ quay về backend trên máy này. Native
client chưa chọn server mở màn hình kết nối mà không gửi request đến origin của
WebView. Fixture kiểm các trường hợp này, gồm không gửi cookie đến managed
backend, không đọc vault local và hủy context khi đổi server.

119 UI test pass, TypeScript và ESLint đạt. Production bundle và packaged UI
assertions pass. Các phép thử dùng transport fixture.

## Windows process supervisor và credential vault

Rust supervisor tạo token ngẫu nhiên, giữ stdin mở và xác nhận readiness đúng
định dạng trên `127.0.0.1` trước khi trả origin. Windows Job Object sở hữu tiến
trình và các tiến trình con. Shutdown đóng pipe, chờ tối đa 12 giây, rồi đóng job
để dọn các tiến trình còn lại. Credential Manager lưu credential theo canonical
origin trong namespace Orion và hỗ trợ đọc, thay thế, xóa riêng từng origin.

Native HTTP transport giới hạn request theo origin và nhóm header API. Transport
gắn token managed trong Rust, hỗ trợ đọc body từng chunk và từ chối redirect.
Remote HTTPS dùng kiểm chứng TLS của Windows. Đã kiểm fixture loopback cho dữ
liệu chia chunk, chặn redirect và giữ header resume `Last-Event-ID`.

Rust 1.99.1 Windows x64 GNU chạy qua cả sáu test, Rustfmt và Clippy đạt. Bài
supervisor khởi động đúng `OrionBackend.exe` có SHA-256 ở trên, xác nhận HTTP 401
khi thiếu hoặc sai token và HTTP 200 qua transport managed. Cổng đóng khi shutdown
và database còn lại. Bài vault dùng hai origin thử nghiệm khác port, kiểm
đọc/đổi/xóa độc lập và dọn cả hai entry. Windows CI đã có lệnh chạy lại các bài
này.

## Tauri source

Tauri window dùng SPA đóng gói và memory history. Capability chỉ mở các lệnh
Orion cho cửa sổ chính. Source có single instance, quản lý sidecar, Credential
Manager qua IPC, raw binary upload, đọc stream theo yêu cầu và hủy theo signal.
Hai bài UI IPC dùng invoke fixture đã kiểm request/response binary và cleanup khi
abort. Workflow Windows có bước kiểm compilation với feature production.
